## §3.4 → terminations wiring

The predicates are plain `func(env, **params)` callables, so they drop straight into
`TerminationTermCfg`. The **scene keys for peg/socket are the registered asset names**
(`vdash_peg`, `vdash_socket_c{...}`), which vary per build — the task overrides the
`task.yaml` placeholders with the real asset names on a deep copy (`load_task_cfg` is cached, never
mutated in place). The active socket's clearance `c` is injected into `inserted` at build time
(`c=2.0 mm → 0.002 m`, `c=1.0 mm → 0.001 m`, …).

Two `ContactSensor`s on the peg (both auto-`activate_contact_sensors=True` because the peg is a RIGID
object):
* `peg_finger_contact` — filtered against `panda_leftfinger`/`panda_rightfinger` → grasp force (`force_matrix_w`);
* `peg_contact` — unfiltered net force (`net_forces_w`) → `force_violation` / `insertion_failed`.

## §3.5 per-episode log schema

One JSONL record per episode, written in the recorder's `record_pre_reset` (terminal cause resolved
from the termination manager; geometry/force accumulated per-step in `record_post_step`):

```json
{"episode": 1, "env_id": 0, "clearance_mm": 2.0, "result": "success",
 "t_grasped_s": null, "t_handoff_s": null, "t_inserted_s": 0.0167,
 "handoff_dx_mm": 0.0, "handoff_dy_mm": 0.0, "handoff_tilt_deg": 0.0,
 "force_max_N": 0.0, "force_violations": 0, "episode_steps": 1}
```

`result ∈ {success, insertion_failed, dropped, timeout, none}`; `handoff_dx/dy/tilt` captured at the
step `handoff` first holds; `force_max_N`/`force_violations` running over the episode.

## Fixes made during M2

* **Scene-key mismatch** — predicates referenced `peg`/`socket` but scene keys are the registered
  asset names; the task now overrides them with `peg.name`/`socket.name`.
* **L0 was not actually fixed** — the at-reset pose randomizer (run even with an empty L0 range)
  relocated the peg to ≈origin (`tip_z=-0.002`, lat 3.77 mm) → table penetration → 2289 N. Fixed: at
  L0 (empty `pose_range`) the randomizer term is `None` (skipped) and `reset_scene_to_default`
  restores the canonical poses; randomization is added only for L1+.
* **Optional event fields** — `combine_configclass_instances` copies only declared dataclass fields,
  so L2/L3 lighting/texture terms are **declared** on `EventsCfg` (default `None`, skipped by the
  EventManager) rather than `setattr`-ed.

## Known issues / decisions

* **c ≤ 1.0 mm `--preinsert` step-1 force spike (171 N @ c=1.0, 2289 N when penetrating)** is the
  M1-documented SDF spawn transient: teleporting a peg into a tight SDF bore produces a one-step
  corrective impulse that ejects it laterally past the clearance bound. This is a property of the
  *instantaneous teleport* initial condition, **not** the task wiring — M3's force-limited controller
  lowers the peg gently (no teleport) and is where tight-clearance insertion is exercised. The success
  path is cleanly demonstrated at c=2.0 (zero contact at spawn).
* **`force_max=50 N` / `grasp_force=1 N` remain provisional.** Clean seating shows ~0 N; the tight
  teleport shows 100s of N. Full calibration needs the real (gentle) insertion force profile from the
  M3 controller — deferred to M3.
* **L2/L3 visual randomization (lighting/texture/distractors)** is wired but validated only by
  construction here; visual confirmation belongs with a camera/WebRTC run (`LIVESTREAM=2`).
