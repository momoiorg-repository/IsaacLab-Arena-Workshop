## Known risk → M3: intermittent off-axis SDF explosions ⚠
Larger off-axis approaches intermittently blow up (vmax 50–70 m/s, peg ejected). This is a PhysX
**SDF rigid-contact instability on grazing approaches**, and it did **not** improve across the
levers swept:

| lever swept | values tried | effect on explosions |
|---|---|---|
| SDF resolution | 256 → 512 → 1024 | none |
| mesh tessellation | 96 → 256 sections (297→777 verts) | none |
| contact_offset | 5 mm → 0.2 mm | helped *entry*, not explosions |
| harness model | constant-force → impedance → gravity | gravity removed ramming; residual remains |

Root cause is open-loop rigid contact driving the peg into pathological grazing configs. The
brief **mandates** SDF for the bore ("convex 近似では穴が成立しない"), so the collision type can't change.

**Why this is acceptable to carry into M2/M3:** the brief's real insertion is **EE-held and
force-limited** (push 2–5 N, retreat on force-exceed, xy spiral search). That controller
structurally avoids ramming the peg into the configs that explode here. The standalone open-loop
drop harness is a worst case. ⇒ **definitive insertion-stability validation = M3** (`insertion_controller.py`).

### Mitigations available in M3 if explosions recur under force control
- Cap contact force / `max_depenetration_velocity`; reduce physics dt (1/120 → 1/240) near contact.
- Force-thresholded retreat + spiral search (already in the brief's controller spec).
- Fallback: thin-walled convex-decomposition *sleeve* around the bore (a coarser but rock-solid
  convex-vs-convex approximation) if SDF proves unworkable under force control.
